# regime-scan --interval 4h (2026-08-20, 3-hourly check)

## Why

The 18:55 UTC `regime-scan` run (see `runs/2026-08-20-1855-regime-scan-melt-up-concentration.md`)
measured concentration of compounded growth on the 1d bar track and flagged one
cheap follow-up: does the 4h track show the same concentration before any 4h
fold redesign is worth designing? This run answers that.

## What ran

```
python3 evotrader_bundle.py regime-scan --interval 4h
```

Read-only, genome-independent (equal-weight buy-and-hold only, no genome or
Council involved), no state write. Took ~6m15s wall time (slower than the 1d
track's usual sub-minute cost — 8,766 4h bars vs ~1,460 1d bars over the same
calendar span, ~6x the data to fetch/process, consistent with every other
1d-vs-4h cost ratio observed in this repo's shadow-evolution runs).

## Reading

Directly comparable to the 1d track's own n=12 scan from the 18:55 run, which
found a 2.45x concentration ratio at the same window count. The two numbers
agree to within noise (2.47x vs 2.45x) — this is the same order of magnitude,
not a coincidence of binning. The richest window here (w8, 2024-08-14 to
2024-11-25) overlaps the same melt-up the 1d n=12 scan identified as one of
its two separated bull runs (2024-08 → 2024-11, +102.1% in the 1d scan's own
numbers) — same underlying market event, seen from both bar sizes.

This closes the question the 18:55 run left open: the concentration isn't a
1d-specific artefact of that track's particular bin edges. Any future
regime-stratified fold-scheme redesign is motivated the same way and can use
the same regime label (`regime-scan`'s own per-window buy-and-hold return) on
either bar size without re-deriving the case for it.

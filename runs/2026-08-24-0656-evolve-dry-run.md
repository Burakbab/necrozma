# evolve-dry-run: the second and final piece of item 7's tick/evolve cutover

2026-08-24, 3-hourly check, ~06:56 UTC.

## What

`run_from_files.py` gains `evolve-dry-run`, alongside the existing
`tick-dry-run`. It runs the real self-improvement search
(`loop.evolve.EvolutionRun`, the exact class `evotrader_bundle.py`'s
`evolve` command drives) against the real files -- market data, the
Researcher's proposals, walk-forward fold evaluation, the sealed holdout --
but never calls `acct.save()`, on any code path, whether a candidate would
have been promoted or the champion would have held. This was AGENTS.md item
7's explicitly-flagged "actual cutover" remainder: `tick`/`evolve` saving
against the real files. `tick-dry-run` (2026-08-23/24) covered the first of
those two state-mutating commands; this covers the second, and with it,
both of the commands `run_from_files.py` was missing relative to the
bundle's live command set are at least dry-run-safe now (a saving cutover,
and the decision to ever schedule a run against this file instead of the
bundle, both remain separate and are explicitly not attempted here).

The command body is transcribed verbatim from `evotrader_bundle.py`'s own
`evolve` cmd, including resuming `acct.researcher_memory` (so the
multiple-testing bar / boldness keeps climbing the same way a resumed real
`evolve` invocation would), with one addition: an optional `--seed N` flag
(the bundle's own `evolve` always passes `seed=None` for genuine randomness
on a live run) so this file's own test suite can make a run reproducible.

## Why this needed a new, bigger synthetic fixture

The existing `tick-dry-run` synthetic fixture (`ZZTESTAUSDT`/`ZZTESTBUSDT`,
600 daily bars, ~1.64y) covers `LiveAccount.tick()`'s 1.5y `load_universe`
window with margin, but `evolve` calls `market.load_universe(g0.universe,
g0.bar_interval, 4.0)` -- a 4-year window. Reusing the 600-bar fixture for
`evolve-dry-run` triggered `core.market.load()`'s "need older history"
branch, which then tried (and failed) to fetch the fake symbols from the
real Binance API. New `synthetic_universe_4y` fixture generates ~1500 daily
bars (>4.1y) per fake symbol instead, same synthetic-random-walk generator,
same discipline of cleaning up the cache files afterward regardless of test
outcome.

A second, non-obvious safety wrinkle: `EvolutionRun` doesn't only touch
in-memory `acct` state -- `Genome.save("champion")` / `.promote()` (called
by `evolve`'s own setup and by any accepted candidate) writes real files
under `state/genomes/`, and `EvolutionRun._record` appends every generation
to `state/lineage.jsonl`. Confirmed both resolve to the *same* absolute
path in bundled and real-files mode (the bundle's meta-path loader sets
`module.__file__` to a path like `"core/genome.py"`, resolved relative to
cwd at import time -- same as the real package's own `__file__` when
imported from the repo root), so a naive dry-run test leaving fake-universe
genome archive files behind really could sit in the same directory a real
`evolve` invocation later reads via `Genome.champion()`. Traced whether
that's actually dangerous: it isn't, provably -- `evolve`'s own `evolve`
(bundle) *and* `evolve-dry-run` (real files) both call `g0.save("champion")`
with the real `acct.genome` as the very first thing they do, before
`EvolutionRun.run()` ever calls `Genome.champion()` itself, so any stale
`champion.json` is self-overwritten before it could be read; and grepping
the whole real codebase confirms nothing outside `core/genome.py` itself
reads `state/genomes/*.json` back in (the live trading path reconstructs
the champion from `live_state.json`'s own genome + lineage, never from
these archive files). `state/` is gitignored and the `.gitignore` already
documents this ("durable runtime state -- genome archive + market cache are
rebuildable side effects of `evolve`, not the source of truth"). Still,
`synthetic_universe_4y` snapshots and restores `state/genomes/` and
`state/lineage.jsonl` around the test as defense-in-depth / plain
cleanliness, even though the corruption path it guards against is inert.

## New tests, both in `tests/test_run_from_files_matches_bundle.py`

- `test_evolve_dry_run_never_saves_state` -- 1 generation, `--seed 7`,
  against the synthetic 4y universe: asserts the scratch state file
  (`EVO_STATE` override) is byte-identical before and after, the real
  `live_state.json` never moves, and the run reports either "champion
  would have held" or "would have promoted champion" (accepts either --
  the point is the dry-run guarantee holds regardless of which happens,
  not which one this particular seed happens to produce).
- `test_evolve_dry_run_resumes_researcher_memory` -- seeds a scratch
  `researcher_memory` with `stagnation=5` two ways: `champion_version`
  matching the seed genome's own version (must resume -- output shows
  `boldness 5`) and mismatched (must NOT resume -- output shows
  `boldness 0` regardless of what the stale memory claims). Checked via
  the `Researcher.propose`/`generation()` log line's own "boldness N" text
  rather than trying to reconstruct the internal excluded-proposals key
  format from stdout, which the code makes no promise to expose in a
  parseable form -- a much more direct assertion of the actual resume
  wiring in `_cmd_evolve_dry_run` than parsing candidate dicts would have
  been.

# exit-role-test: quantifying the exit-mechanism finding (2026-08-27, ~18:54 UTC)

## Why

The 09:56/12:54/15:49 UTC `history-perturb --anatomy` entries found the same
exit-mechanism pattern on 3/3 independent windows: `consult_moderate`'s and
`consult_risky`'s own discretionary exits lose money while Guardian's
mechanical exits (stop loss / trailing stop / take profit / time stop) profit
heavily. The flagged next step was a real gene/threshold change (tighten
those two consults' exit conditions toward guardian-style mechanical stops)
validated with a shadow `evolve` run — explicitly flagged as bigger than one
3-hourly slot.

This session built the cheap version first: a new read-only diagnostic,
`exit-role-test`, that tests the limit case directly — what if
`consult_moderate`/`consult_risky` didn't have their own exit rule at all,
and every position they'd have sold instead just rode until Guardian caught
it? Same precedent as `consult-role-test` (monkeypatch `.consider` for a few
extra `run_backtest` calls, restore in `finally`, nothing persisted).

## What it does

`python3 evotrader_bundle.py exit-role-test [--also-version N]`

Runs the full-history backtest four ways: baseline (as tuned), with
`consult_moderate`'s own sell intents suppressed, with `consult_risky`'s
suppressed, and with both suppressed. Buy rules are untouched in every
variant. Guardian's `forced_exits` runs every bar regardless of consult
output (`loop.engine.Council.tick`), so no position is ever stuck unexited —
suppressing a consult's sell intent just means Guardian's mechanical stop
takes it instead of the consult's discretionary call.

## Results

**v3 (live champion), full 4-year history, 27 symbols:**

| variant | fitness | return | maxDD | trades | excess vs b&h |
|---|---|---|---|---|---|

## Reading

1. **`consult_moderate`'s exit rule is the real problem, on both champions
   checked.** Suppressing it alone takes v3 from a hard-gate-failing -46.5%
   maxDD to a passing 0.659 fitness (+190.3% excess vs +90.1%), and improves
   v2 too (0.169 → 0.396). Consistent direction on two independent genomes —
   this is the strongest single lever the anatomy thread has found, and
   matches the anatomy runs' own ranking (moderate's own exit was the
   largest or near-largest loss category in every window checked).

2. **`consult_risky`'s exit rule is genome-dependent, not a general problem
   — and the two champions disagree in direction, not just magnitude.** On
   v3 it's a complete no-op (every stat identical to baseline to the
   decimal — the exit condition apparently never fires as the actual selling
   agent for this genome's parameter values). On v2 it's actively load-bearing:
   suppressing it *hurts* badly (fitness 0.169 → -inf, maxDD blows out to
   -43.4%). This is the same "search already corrected it for the current
   champion, don't assume it generalizes" shape as the closed
   `consult-role-test` finding on `consult_conservative`'s entries
   (2026-08-23 entry, item 8). **Do not build a blanket "suppress/tighten
   consult_risky's exit" gene** — any real change needs its own
   champion-specific check, not an assumption from the v3 numbers alone.

3. **"Both suppressed" is not simply additive and not always the best
   variant.** On v3, `both` has *higher* return and *lower* maxDD than
   `moderate exit suppressed` alone (+405.7%/-37.5% vs +296.8%/-39.1%) but
   *lower* fitness (0.484 vs 0.659) — fitness is Sortino-shaped plus
   turnover/DD penalties, not a monotone function of return or maxDD alone,
   and 508 trades vs 824 changes the turnover term. Don't read fitness deltas
   here as "closer to the eventual gene's effect than the return numbers" —
   they're both just diagnostic, neither is the target the real gene search
   would be argued against.

## What this justifies and what it doesn't

This is evidence for building a real `consult_moderate` exit-threshold gene
change (tightening `exit_trend_below`/`exit_rsi` toward less-frequent firing,
or removing the discretionary exit from the entry role entirely and letting
Guardian handle it) and letting a shadow `evolve` run decide the actual
threshold — not a promotion case, and not the gene change itself. It also
narrows the original flagged scope: `consult_risky`'s exit does NOT belong in
the same gene change given point 2 above; only `consult_moderate`'s does,
at least until checked against v1 too.

**Next**: check v1 with `--also-version 1` for a third data point on the
risky-genome-dependence question; then sketch the actual
`consult_moderate` exit-threshold gene (narrower literature range around
`exit_trend_below`/`exit_rsi`, or a hard "no discretionary exit, entry role
only" variant) and validate with a shadow `evolve` run against the
unmodified champion on the same folds. Still genuinely untried, no gene code
sketched — the shadow-evolve validation alone is likely another full
3-hourly slot given `n_blind` defaults and full-search cost.

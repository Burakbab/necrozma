# fold3-anatomy: what actually drives fold 3's hard-fail, and does the exit gene touch it?

2026-08-28, 3-hourly check, ~04:04 UTC.

## Why

The 00:56 UTC `exit-gene-test` entry (AGENTS.md Current state) found both
`consult_moderate` exit-gene candidates hard-fail `MAX_DD_HARD_FAIL` (0.40)
because of fold 3 (`[0.567, 0.85]` of history) -- champion v3 itself already
fails it there (-46.80% dd-corrected `max_dd`) before any candidate is ever

## What this ran

New CLI command `fold3-anatomy` (`evotrader_bundle.py`, CLI-only code, no
`_SRC` module touched -- same category as `exit-gene-test`). Read-only.

**First version of this diagnostic (not shipped) had a real bug, caught
before committing**: it assumed `dd_corrected_stats()`'s `min(fold-merged,
continuous)` correction always picks the continuous (boundary-free) replay,
and ran only that. Checking the actual gate call directly showed the
opposite for both champion v3 and the "no discretionary exit" candidate:
`_merge()`'s fold-merged `max_dd` is a `min()` across each fold's own
*independently-reset* backtest, and for both genomes that merged number
(-46.80% / -45.76%) is *more negative* than the continuous one (-46.5% /
-34.7%) -- so fold-merged is what actually binds, and it's driven entirely
by fold 3's own fresh-broker replay, not the continuous span. The
continuous-only version would have reported the "no discretionary exit"
candidate at -34.7%, i.e. *clearing* the hard-fail gate -- which is simply
wrong; the real gate uses -45.76%, still a hard-fail, exactly matching
exit-gene-test's own number. Fixed version computes both fold-local (all 3
folds, run independently) and continuous, confirms via
`dd_corrected_stats()` which one is actually binding, and runs the
trade-level analysis on that specific replay.

## Result

Both champion v3 and "no discretionary exit" bind on fold 3's own
independent replay (fresh cash, fresh state at `0.567` of history):

| | fold 1 | fold 2 | fold 3 (binding) | continuous | gate value |
|---|---|---|---|---|---|
| champion | -32.7% | -32.6% | **-46.8%** | -46.5% | -46.8% |
| no discretionary exit | -32.9% | -32.5% | **-45.8%** | -34.7% | -45.8% |

Both reproduce exit-gene-test's own numbers exactly (-46.80% / -45.76%,
small rounding). The exit gene buys almost nothing inside fold 3 itself: one
point of depth (-46.8% -> -45.8%), nowhere near the ~7-point gap to clear
0.40.

Trade-level listing of the 10 worst closed trades inside fold 3's own
drawdown episode (2024-12 to 2025-06) is **nearly identical between the two
variants** -- same symbols, same dates, same P&L, same exit mechanism:
ZECUSDT (-30.9%, guardian time stop), XRPUSDT (-19.8%, time stop), ATOMUSDT
(-20.2%, time stop), FETUSDT (-37.0%, guardian stop-loss), SOLUSDT (-21.3%,
time stop), DOTUSDT (-33.6%, time stop), a second ZECUSDT (circuit-breaker
flatten), HBARUSDT (time stop), CRVUSDT (time stop), LTCUSDT (time stop).
**Every one of the 10 worst trades exits via Guardian's mechanical stop-loss,
time-stop, or the circuit breaker -- none via `consult_moderate`'s own
discretionary sell decision.** That is the direct answer to the open
question: suppressing `consult_moderate`'s exit cannot meaningfully touch
fold 3's drawdown, because the losing positions in this window were never
going to be closed by that exit in the first place. The exit-gene-test
finding and fold 3's hard-fail are two different problems that happen to
share a champion, not the same lever restated.

## Next

Fold 3's own drawdown is driven by Guardian's mechanical exits (stop-loss,
time-stop) and one circuit-breaker flatten across a cluster of positions
opened in a narrow Dec 2024 window plus a scattered set of Jan-Mar 2025 time
stops -- not by any discretionary consult decision. A real fold-3-scoped fix
would have to target one of those mechanisms (e.g. the stop-loss/time-stop
thresholds themselves, or position sizing/correlation limits that let this
many positions open into the same adverse move at once) or accept that v3
may simply be structurally exposed on this specific historical window.
Whether that's worth pursuing as a real gene change -- and whether it's a
different regression than the ones `fold-dd-blindspot`/`succession-audit`
already tracked -- is genuinely open and untried.

## One mistake caught mid-run, corrected

Ran the post-evolve full test suite as `python3 -m pytest -q > log 2>&1 &`
inside a tool call already using `run_in_background: true` — exactly the
"never pair a trailing `&` with the tool's own backgrounding" anti-pattern
AGENTS.md item 9 documents. The wrapper reported "completed" while the real
pytest process (PID 2743) kept running detached. Caught immediately via
`ps aux | grep pytest` before treating the empty tail as a pass; re-waited
correctly by polling `kill -0 2743` directly (single backgrounding mechanism,
no `&`) until the real process exited. No harm — just re-spent attention on
an already-documented mistake. Not re-litigating item 9 itself; recording
this instance in case the pattern recurs enough to justify strengthening the
existing `tools/background_runner.py` guard further (e.g. warning if a
caller pipes to a file with a trailing `&` instead of using `start`/`wait`).

## What ran

```
python3 tools/background_runner.py start --log /tmp/evolve_1846.log \
    --status /tmp/evolve_1846.status -- python3 evotrader_bundle.py evolve 15
python3 tools/background_runner.py wait --status /tmp/evolve_1846.status --poll 10
```

Note: the first `wait` attempt was invoked with an invalid extra `--log` flag
(that subcommand only accepts `--status`/`--poll`/`--timeout`); argparse
errored out immediately, and piping through `tail -60` masked the failure by
reporting the pipeline's own (tail's) exit code as 0. The evolve process was
still genuinely running underneath (confirmed via `ps`). Re-ran `wait`
correctly with only `--status`, which blocked for the real ~34 minutes and
returned the true exit code 0. No output was lost — the child had been
writing straight to `--log` the whole time regardless of the wait command's
outcome. Flagging here in case this bites another session: always pass
`wait` only the flags it defines, and never pipe its own or `start`'s
invocation through anything that could substitute a different command's exit
code for the real one.

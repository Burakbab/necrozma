## Git-sync incident (read this before trusting "tick 43" anywhere else)

This run hit a real instance of the shallow-clone/stale-ref trap AGENTS.md already warns
about, worth recording precisely since it produced a bad tick that could have been pushed:

- `git checkout main` at the start of this run reported "up to date with origin/main"
  **without an explicit fetch having run first** — a stale cached ref, not a real check.
- Running `python3 evotrader_bundle.py tick` against that stale state produced a tick
  labeled **43**, deciding bar **2026-09-27** directly after the local journal's last real
  entry (tick 42, bar 2026-09-24) — silently skipping over two ticks (real tick 43, bar
  2026-09-25; real tick 44, bar 2026-09-26) that had already executed elsewhere and were
  already on `origin/main`. The command itself gave no warning — no "already traded"
  message, since bar 2026-09-27 genuinely hadn't been traded *in this stale copy of state*.
- Caught before push: `git push` was rejected as non-fast-forward (23 commits behind).
  Fetching `origin/main` and inspecting its `live_state.json` directly showed it already
  had tick 43 (bar 2026-09-25, NAV $14,785.21) and tick 44 (bar 2026-09-26, NAV $14,836.54)
  — real trades this session's stale tick would have duplicated/overwritten tick numbers
  for and, if pushed, corrupted the journal's tick sequence.
- Fix: discarded the two bad local commits (working tree was clean, nothing else at risk),
  `git reset --hard origin/main` to adopt the canonical state, `tools/git_sync.py` confirmed
  clean, then re-ran `tick` fresh — correctly produced **tick 45**, bar 2026-09-27, matching
  the real next bar after the canonical tick 44.
- **Lesson, reinforcing AGENTS.md's own existing warning**: `git checkout main` reporting
  "up to date" is not itself proof of freshness — it can be reading a stale cached ref.
  Run an explicit `git fetch origin main` (or `tools/git_sync.py`) *before* the checkout,
  not just before a suspected divergence, especially right before running any
  state-mutating command like `tick`/`evolve`. This run's checkout skipped that and it
  produced a real bad tick, not just a git-history annoyance — caught only because the
  push happened to fail fast-forward, not because anything upstream of the push detected it.

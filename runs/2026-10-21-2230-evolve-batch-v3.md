## First attempt lost to a container restart

Started a baseline `python3 -m pytest -q` (474/474, passed), took a
pre-batch snapshot of `live_state.json`, then started a 15-generation
`evolve` batch via `tools/background_runner.py start`. While waiting on the
background `wait` call, the session's container was restarted (a
harness-level event, unrelated to this repo's code) — the task notification
for the pending `wait` reported the work as lost.

Checked the aftermath directly rather than assuming: `git status` was still
clean and `git log` showed local `main` still matched `origin/main` exactly
(nothing to lose there). The detached `evolve` process itself was gone
(`ps aux` showed no survivor). Diffing `live_state.json` against the
pre-batch snapshot taken before the first attempt showed it was
byte-identical (`updated` timestamp unchanged) — confirmed by checking the
batch's own log file, which had reached generation 12/15 before being cut
off. This is expected and safe: `evolve` only calls `acct.save()` once, at
the very end of the run, so a mid-run interruption leaves `live_state.json`
exactly as it was, never partially written. No special recovery was needed
beyond re-running the batch from scratch.

## Process note (minor, no harm)

A follow-up verification step (pytest + `tools/edit_bundle_module.py sync
--check` + `holdout-pressure` chained in one Bash call) was written with a
trailing `&` to background the whole chain inside a call also marked
`run_in_background: true` by the tool — exactly the double-backgrounding
anti-pattern item 9 warns against, this time on a verification command
rather than `evolve` itself. The tool reported the wrapper "completed"
almost instantly while the real `pytest`/`sync`/`holdout-pressure` chain kept
running detached. Caught immediately by checking `ps aux` for the real PID
still alive, then waited correctly by polling the actual output log file for
its own completion marker instead of trusting the wrapper's reported exit.
No state was touched by this verification step either way, so no risk, but
flagging as a second recurrence of this pattern's root cause (pairing the
tool's own backgrounding with a shell-level `&`) in a context item 9's
existing wording ("don't wrap a backgrounded `evolve`/long-running command
in `nohup ... &`") doesn't explicitly cover — any chained verification
command, not just `evolve` itself, needs the same single-mechanism
discipline.
